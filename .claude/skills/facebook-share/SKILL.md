# 페이스북 공유 준비

사용자는 초등학생 수준의 초보자다. 어려운 용어 없이 짧게 말한다.
사용자가 이 스킬을 부르며 파일을 지정한 것은 **미리보기 설정 추가 + GitHub 올리기(push)에 대한 허락**이다.
페이스북에 직접 게시하는 것은 하지 않는다(로그인 계정 작업, 사용자가 직접 붙여넣는다).

작업 폴더: `D:\claude\portpolio` (GitHub Pages 주소: `https://amangcsk.github.io/portpolio/`)

## 순서

1. **파일 찾기** — 사용자가 준 경로/이름이 정확하지 않으면 `storyboard/`, `stories/` 아래에서 찾는다.
   여러 개가 맞으면 목록을 보여 주고 하나만 묻는다.
2. **설정 넣기** — 이 스킬 폴더의 스크립트를 실행한다(여러 파일 한꺼번에 가능):
   ```bash
   PYTHONIOENCODING=utf-8 python -I "D:/claude/portpolio/.claude/skills/facebook-share/add_og.py" "storyboard/새책.html"
   ```
   (`PYTHONIOENCODING=utf-8`가 없으면 윈도우에서 한글이 깨져 보인다.)
   출력은 `주소<TAB>파일<TAB>결과` 한 줄씩이다. `!`로 시작하면 실패.
   `이미 설정됨`이면 설정은 건너뛰고 3번으로 간다(주소는 그대로 쓸 수 있다).
3. **GitHub에 올리기** — 이번에 바뀐 파일(HTML과 `_thumbs`의 새 표지 그림)만 골라서 add 한다.
   `.bkit/` 등 다른 변경은 건드리지 않는다. 커밋 메시지 예: `새 책 페이스북 미리보기 설정 추가`.
   `git commit`에는 시스템 안내에 있는 Co-Authored-By 줄을 `-m`으로 덧붙인다.
   (`$(... <<EOF)` 형태의 heredoc은 hook에 막히므로 `-m`을 두 번 쓰는 방식을 쓴다.)
   `git push origin main`
4. **반영 기다리기** — 배포(`gh run list -R amangcsk/portpolio -L 1`)가 끝나고,
   `curl`로 주소를 받아 `og:image`(그림이 있는 책이면)와 `og:title`이 보이는지 확인한다.
   표지 그림 주소도 200으로 열리는지 확인한다. 10초 간격으로 최대 약 6분 기다린다(`sleep`은 until 루프 안에서, 백그라운드로).
   배포가 `failure`면 `gh run view <id> --log-failed`를 보고, 일시적 오류(예: `Failed to get ID Token`)면 `gh run rerun <id>`를 한 번 한다.
5. **결과 알려 주기** — 아래 형식으로 짧게:
   - 책마다 **붙여넣을 주소**(한글 그대로 읽히는 형태로 한 줄씩, 복사하기 쉽게 코드 블록)
   - 그림이 있는지(없으면 "글자만 있는 카드로 뜹니다")
   - 페이스북에서 할 일: "무슨 생각을 하고 계신가요?" 칸에 주소를 붙여넣고 → 카드가 뜨면 → 소개 글 쓰고 → "게시"
   - 예전에 같은 주소를 페이스북에 붙여 본 적이 있으면 `developers.facebook.com/tools/debug`에서 "다시 스크랩"이 필요하다고 한 줄 안내

## 주의

- 파일 이름이 한글이어도 주소는 한글 그대로 보여 준다(복사해 붙이면 페이스북이 알아서 변환한다).
- 배포 확인이 끝나기 전에는 "붙여넣으셔도 됩니다"라고 말하지 않는다.
- 책 안에 그림이 없는 이야기책은 표지 그림을 만들 수 없다. 사용자가 원하면 별도 작업으로 제안한다.
- 새 파일이 `storyboard/`, `stories/` 밖에 있어도 포트폴리오 폴더 안이면 동작한다.
